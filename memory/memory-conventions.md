# Memory Conventions

## Fact or rule

- Keep durable project decisions, corrections, and working preferences in `memory/`.
- Read `memory/INDEX.md` at the start of every session; create it when the first note is needed if absent.
- Record confirmed important decisions and user corrections, not temporary tasks or unconfirmed assumptions.
- Keep one topic per note with a fact or rule, why it exists, and how to apply it.
- Check for an existing topic note before adding one. Update existing notes instead of duplicating them, and link each note from the index.
- Correct inaccurate notes; ask before deleting files.
- Treat "remember this" as a request to update memory, not authorization to change unrelated project files.
- Never store secrets or credentials.

## Why

The user selected a structured memory folder to prevent repeated mistakes and preserve decisions across sessions.

## How to apply

Consult the index before work and maintain the relevant topic note when a durable decision or correction is confirmed. The earlier root `MEMORY.md` remains in place because deleting or moving it requires permission; future map-rule updates belong in `memory/map-rules.md`.
